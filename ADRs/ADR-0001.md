# ADR-0001: Event-loop-native HTTP/1.1 on SwiftNIO types

- Status: Accepted
- Date: 2026-09-12

## Context

`yohttp` is a small Swift 6 HTTP server. The public surface, the handler contract,
and the connection pipeline have to stay cheap enough that a synchronous
`/health` write can finish on the same `channelRead(.head)` that invoked the
handler, while still letting application code finish a response later from a
`Task` or actor.

Those two requirements fight: NIO channel I/O is bound to the connection event
loop, `ChannelHandlerContext` is not `Sendable`, and Swift 6 forbids
`@unchecked Sendable` as an escape hatch.

## Decision

### 1. SwiftNIO is the transport and the HTTP vocabulary

The server is HTTP/1.1 on SwiftNIO (`NIOCore`, `NIOHTTP1`, `NIOPosix`, optional
`NIOSSL`). `YoHTTP` re-exports `NIOCore` and `NIOHTTP1`.

There is no parallel HTTP type system. Callers use `HTTPRequestHead`,
`HTTPResponseHead`, `HTTPHeaders`, `HTTPMethod`, `HTTPResponseStatus`,
`HTTPVersion`, `ByteBuffer`, and `SocketAddress` directly.

`Request.head` is NIO's `HTTPRequestHead`. Response heads are initialized with
`HTTPResponseHead`. Bodies are `ByteBuffer` chunks. Query strings stay on
`request.head.uri` until a macro endpoint decodes them.

Do not reintroduce wrapper types for status, headers, cookies, or method.

### 2. HTTP/1.1 only

The pipeline is `configureHTTPServerPipeline()` plus `HTTPConnectionHandler`.
TLS, when configured, is PEM key+cert with ALPN `http/1.1`. No HTTP/2, no
protocol upgrade API.

### 3. Handlers are synchronous and run on the connection event loop

```swift
typealias Handler = @Sendable (consuming Request, borrowing Response) throws -> Void
typealias Middleware = @Sendable (consuming Request, borrowing Response, Next) throws -> Void
```

`HTTPConnectionHandler` calls the handler from `channelRead(.head)`, before the
body has finished. The function is `throws`, not `async`. Callbacks on
`BodyStream` (`onChunk` / `onEnd` / `onError`) also run on that loop.

Blocking the handler or those callbacks blocks the connection. Expensive or
isolated work is the application's problem: hop off the loop, then complete
through `ResponseWriter`.

Do not make `Handler` async. Do not hop onto a library executor before
`handle`.

### 4. `Request` and `Response` are move-only capabilities

Both are `~Copyable` and `Sendable`.

The handler **consumes** the request and **borrows** the response. That is the
macro contract:

```swift
func handle(_ request: consuming Request, _ response: borrowing Response) throws
```

`Request` is the unique owner of the body stream and the routed parameter map.
Passing it to `next` or into a stream callback transfers that ownership.

`Response` cannot be stored past `handle`. To write from a stream callback,
`Task`, or actor, call `response.writer()` and retain the copyable
`ResponseWriter`.

### 5. Response is a one-shot command mailbox, not a buffered document

`Response` / `ResponseHead` / `ResponseWriter` enqueue commands:

`initialize(HTTPResponseHead)` → optional `modify` → `commit` | `write` | `end`

The connection handler is the only writer to the socket. It stages the head
until `commit`, `write`, or `end`. `write`/`end` commit automatically.
Modifiers that arrive before commit are applied in order; after the head is
flushed they are ignored. A second `initialize` after the head exists, or any
write without an initialized head, fails the request (500 if nothing has been
sent, otherwise the connection is closed).

`ResponseWriter` is the retainable handle. It is `Sendable` so application-owned
work can finish the response on another executor.

### 6. Cross-thread completion hops through `ConnectionSignal`

`ChannelHandlerContext` stays inside `HTTPConnectionHandler`. Off-loop code
never sees it.

`Response` commands and body pause/resume go to `ConnectionSignal`: append
under a `Mutex`, `eventLoop.execute`, then
`pipeline.fireUserInboundEventTriggered` so the inbound handler can drain on
the loop with a real context.

Request identity is a per-request `UUID`. Stale commands after the request
completes are dropped.

This hop exists because `ResponseWriter` is `Sendable`. On-loop writes still
take it; do not "optimize" by handing `ChannelHandlerContext` to user code.

### 7. Bodies are single-subscriber streams; the library does not buffer them

`Body` is a handle to one `BodyStream`. One `onChunk` subscriber. No chunk
callback means the bytes are discarded. `pause()` / `resume()` toggle
`ChannelOptions.autoRead`.

The server counts bytes against `maxRequestBodySize` and fails the stream with
`.tooLarge` (413). It does not assemble `Data` for the application. JSON
buffering, if any, lives in the endpoint.

Channel teardown fails the stream with `.cancelled`. Request timeout fails it
with `.timedOut`.

### 8. One in-flight HTTP/1.1 request per connection

A new `.head` while `current != nil` closes the channel. No pipelined request
dispatch.

`end` before the request body has finished sets `forceClose`. Keep-alive
continues only when the request completed, the response completed, the client
asked for keep-alive, and the handler did not force close.

`HEAD` response bodies are not stripped by YoHTTP; NIO's encoder suppresses
them.

### 9. Timeouts are split across the request/response boundary

`requestTimeout` covers head through body end → 408 and close.

`responseTimeout` starts when the body ends. If the head is still uncommitted
→ 504. If bytes have already gone out → close.

`listen` binds and awaits the listener `closeFuture`. `shutdown()` from another
task closes the listener and active connections. Default runtime is **one**
event loop; raise `ServerRuntimeConfiguration.eventLoopCount` only with a
measured need.

### 10. Errors that leave `handle` become HTTP responses

`HTTPError` (`Abort`) maps to its status, headers, and body. Any other thrown
error is 500 with `Internal Server Error`. Errors after the response has
started cannot rewrite the status; they close.

### 11. The router is a frozen table of macro endpoints

`@Route` attaches only to a struct and emits `RouteEndpoint`:
`routeDefinitions` plus `static respond`. Path `{name}` / `{*name}` must match
`@PathParam` properties. `@QueryParam` is optional-or-required decoding from
`request.head.uri`. Invalid / missing values throw `Abort(.badRequest)`.

Supported methods: GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS. Duplicate
method on one `@Route` is a compile error. Duplicate method+shape at
registration is a programming error. Wildcards are final only.

Match rank: literal (100) > parameter (10) > wildcard (0), then registration
order. `HEAD` falls back to `GET`. `OPTIONS` is synthesized with `Allow` when
missing. Known path, wrong method → 405 + `Allow`. Unknown path → 404.

Configure routes and middleware, then `registrationLocked()`. The snapshot is
an `AtomicLazyReference` and is read without the registration mutex. Registering
after lock, locking twice, or serving before lock is a programming error.

`group` shares that table and prefixes literal segments. Middleware is
prefix-filtered and wrapped outside-in.

`YoHTTPRouter.handler` is a `Handler`. The server does not know about routing
except `server.handler(router)`.

### 12. Strict Swift 6 concurrency

Library types and escaping closures are `Sendable` without `@unchecked Sendable`.
Shared mutable state uses `Mutex` / `AtomicLazyReference`. The event loop is
the isolation domain for channel I/O; everything else hops explicitly.
